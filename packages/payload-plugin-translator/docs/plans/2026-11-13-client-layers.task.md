# Client layers

Build step: 2026-11-13-admin-ui-on-stubs.design.md #4

## Requirements / Task restatement

The admin client is organised as `app > widgets > features > entities > shared`, but nothing holds
that order: entity hooks read their config from `app/`, and any file may import the server, the
core or `ofetch`. This step makes the order a checked rule (R5) and adopts the reference
projects' throwing context and lint-confined imports (R6).

- **Config context.** `TranslateKitConfigContext` moves from `client/app/config/` to
  `client/shared/config/`. Its value is the wire `TranslateKitConfig` (`basePath`, `abilities`,
  `collections`). `useTranslateKitConfig()` throws `TranslateKitConfigMissingError` outside its
  provider instead of falling back to a default `basePath`. `CacheProvider` keeps its public path
  and default export and hands the whole config it receives through `clientProps` to the provider.
- **Dead code.** `client/shared/lib/utils/errors/handleApiError.ts` has no importer and is deleted.
- **Declared boundary edge.** `entities/translation/model/autoTranslateSummary.ts` imports
  `core/domain`; it is renamed `autoTranslateSummary.server.ts`, which makes that edge a boundary
  file's edge.
- **Lint zones** in the repo's `oxlint.config.ts` for `src/client`:
  - C1: client files do not import `src/core`, `src/server` or `src/composition`; they may
    `import type` from `src/types/**` and import values only from `src/types/wire/**`.
  - C2: imports go strictly down the layer order; a feature never names `features/`, a widget
    never names `widgets/`.
  - C3: boundary files (`*.server.ts(x)`, `*.export.ts(x)`) may also import `src/server/shared`
    and `src/core/domain`.
  - C4: no runtime `payload` / `@payloadcms/*` import in `entities/*/{model,api,queries,mutations}`;
    type imports stay allowed.
  - C5: `ofetch` only in `client/shared/api/**`, plus a temporary allowance for
    `entities/translation/api/**` that the legacy sweep (build step 12) removes.
  - A client-tests override turns the zone off under `src/client/**/__tests__/**`.
- **Scan and probe tests:** `layersHold.test.ts` (upward and sibling edges over every relative
  import), a lint probe test (each zone refuses a probe file), `componentPaths.test.ts` (every
  `*.export` class's `path` resolves to a file exporting the component).
- **Written rules:** a "Client layers" section in the package `CLAUDE.md`.

## Decisions

- **The provider takes one `config` prop,** and `CacheProvider` memoises it from the three fields
  Payload spreads from `clientProps`. Rejected: spreading the fields into the provider, which
  restates the wire type's field list in a second signature.
- **The missing-provider error is a class in the context file,** so a test can name it. Rejected:
  an `errors/` folder for one class in a module of one file.
- **The live `handleApiError.ts` moves from `shared/lib/errors/` to `shared/api/`.** It imports
  `FetchError` from `ofetch`, which zone C5 confines to `shared/api`; fixing the edge is preferred
  to exempting the file. Its successor (`ApiRequestError`, build step 6) lands in the same folder.
- **The `ofetch` allowance covers all of `entities/translation/api/**`,** not only `queries/`:
  today's mutation hooks also call `ofetch` and only move in build step 7.
- **C4 uses `allowTypeImports`,** which the installed oxlint (1.64) supports; the fallback of
  banning only `@payloadcms/ui` values is not needed.
- **Zones are generated by one function per (layer, boundary, payload-free, ofetch) combination,**
  ordered broad → specific, because options replace and the last matching override wins: every
  override restates the full rule set for its files.
- **Sibling features and sibling widgets are caught by the scan test, not lint.** A path glob sees
  `../../other-feature` only as text; lint catches only specifiers that name `features/` or
  `widgets/`.
- **The lint probe writes its probe files into a temporary folder under `src/client/<layer>/`,**
  runs oxlint from the repo root on that folder with the repo config, and removes the folder
  afterwards. Rejected: fixed probe files committed outside `src`, which the zones' globs would
  have to name.
- **Probe specifiers point outside `src/client`, and both scans skip `__*__` folders.** Vitest runs
  test files in parallel, so the probe files exist while `layersHold` and `componentPaths` scan the
  tree: a probe target outside the client is invisible to the layer scan, and a folder named like
  `__tests__` never ships, so the export scan does not read the probe's `*.export.ts`.
- **`componentPaths.test.ts` reads the `*.export` sources as text** and resolves the
  `clientComponentPath(...)` argument. Rejected: importing the targets, which pull in
  `@payloadcms/ui` that vitest cannot load, and constructing the classes, whose constructors need
  per-class fixtures.
- **`autoTranslateSummary.server.ts` is renamed, not retired:** `CollectionFacts` replaces it in
  build step 12.

## Risk notes

- Hosts or tests that render a widget outside `CacheProvider` now fail loudly instead of calling
  `/api/translate`. That is intended (migration note owed by the legacy sweep).
- Path-glob zones are textual: a specifier that reaches a forbidden root without naming it (none
  exist) would pass lint; the scan test resolves paths and covers the layer order.
- The C5 allowance for `entities/translation/api/**` is temporary; leaving it after build step 12
  would let new code bypass the shared request.
