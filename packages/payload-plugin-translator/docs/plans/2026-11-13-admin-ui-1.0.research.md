# Admin UI 1.0 — mapping the new design onto what the plugin does today

Part of the next major. Research only: what the new admin design asks for, what of it the plugin
already provides, what is missing, and what the plugin provides that the design drops.

Source: 2026-11-13-admin-ui-1.0.research.source.local.md

Design: canvas "Translator admin — 1.0" (8 boards in three rows — on a document, on a collection,
on a field).

The server half of this design is already decided in
[2026-10-23-what-the-admin-needs-from-the-server.md](./2026-10-23-what-the-admin-needs-from-the-server.md)
("settled in design, not built"). This research does not re-open it: where the two agree, that
document is the design; this one records only where the canvas goes beyond it or disagrees with it.

## Problem statement

The translator's admin UI today is three small popovers (document, list, field) that queue whole
runs and report run status. Since it shipped, the engine gained per-leaf provenance, a stale rule,
leaf-level selection and block-instance addressing — none of which the UI exposes except a
"stale" label. The new design turns the UI into a status-first surface: every locale, every list
row and every field says whether its translation is current, and the editor translates exactly what
is behind. The server read model behind it is designed (2026-10-23) but not built; three of the
canvas's needs are not covered by that design, and two of its choices contradict it.

## Requirements

### On a document (boards Main, DocumentTree, FirstTranslation, NoProvenance)

- R1 (in) The document panel lists every target locale with exactly one state — up to date, N fields behind, not translated, translating, failed (with a short reason), written by hand — and one action fitting that state (none / Update / Translate / Cancel / Retry / Translate).
- R2 (in) The source locale is chosen once, in the panel header, and every action in the panel and the field control's default use it.
- R3 (in) A "behind" locale also flags how many of its behind fields came back empty in the last run, as a distinct failure mark beside the count.
- R4 (in) Expanding a locale shows a field tree that mirrors the saved document: block instances by id with a label, parents carry the count of what is behind, leaves carry a mark only, with the reason in a tooltip.
- R5 (in) The tree has a text filter, a Behind / All switch, a checkbox per node (parent tri-state), a collapsed line for the fields excluded from translation, and a button that translates the ticked subset into that locale, showing "N of M fields".
- R6 (in) A locale with no content shows the tree without checkboxes and one "translate all N" action, with the reason (required localized fields) behind an info mark.
- R7 (in) A locale that has content but no record of any run is shown as written by hand, warning that translating overwrites someone's work.
- R8 (in) With provenance off the panel keeps its shape but drops every mark, the drift wording and the expandable rows; locales read "Translated" / "Not translated" with "Translate again" / "Translate".
- R9 (in) The panel footer carries a "Translate all" action and a one-line note naming the locales auto-translated and when.

### On a collection (boards CollectionList, CollectionDrawer, CollectionEmpty)

- R10 (in) The collection list gains a "Translations" column: one chip per locale per row in the same state vocabulary, with a legend behind an info mark, loaded in one request per list page.
- R11 (out) Filtering or sorting the list by that column.
- R12 (in) The list's selection bar gets a "Translate · N" button whose count follows the ticked rows.
- R13 (in) The collection panel for a selection offers target locales as checkboxes, an "only what is behind" switch with the field count across the selection, the selected documents with their own field count (or "running", or "all N" with the reason when the locale is empty), removal from the selection, and the number of runs that will be queued.
- R14 (in) With nothing ticked, the collection panel offers to translate everything the current list view shows — its search, filters and sort — with the count, or to go back and pick rows.

### On a field (board FieldControl)

- R15 (in) The field control is one Translate button plus an arrow that overrides the source locale for this field only; the panel's source locale is the default.
- R16 (in) The field shows one mark from the same per-leaf verdict as the panel: none (up to date), source moved, not translated, last run never answered; a spinner while asking the provider, and Undo / Again after a translation lands in the form.
- R17 (in) The field control never saves: its value goes into the form, and the mark clears only when the document is saved.
- R18 (in) On a document not yet saved the control is shown disabled with a hint to save first.

### Across all surfaces

- R19 (in) Marks differ in shape as well as colour (filled dot, hollow circle, dashed circle, "!", spinner), up to date has no mark at all, and tooltips open on keyboard focus too.
- R22 (in) The panels have states the canvas does not draw: loading, the status request failing, and a collection with no target locale configured.
- R23 (in) What the panels show is re-read after a translation settles and after the document is saved, not only on page load or tab focus.
- R24 (out) A progress fraction for a running translation.
- R25 (in) A locale a run never attempted, because an earlier locale of the same run failed for good, is shown as its own state ("not started — another locale failed"), with Retry where the runner allows it. The server already stores and reports it as `abandoned`.
- R21 (out) Drift shown below the level of a document's locale, until the end of the major: the "behind the source" chip in the list column (R10), the per-leaf marks in the field tree (R4) and in the field control (R16), the Behind / All switch (R5), and the behind-field count across a bulk selection (R13). The panel keeps "N fields behind" per locale and the unanswered count beside it (R1, R3). Revisited last, once the rest is built.
- R20 (in) [inferred] Nothing the user can do today is removed silently: each current capability the design does not draw (see "Current features the design does not show") is kept, moved, or dropped by an explicit decision — rests on: the plugin is published, and dropping a control in a major still needs a line in the migration notes.

### Where the canvas and 23.10 disagree

- **C1 — drift in the list column.** 23.10 §5 keeps staleness out of the list on purpose: drift needs
  every document on the page read and hashed, so the column says "translated into de, es · 3 days ago"
  or "not translated". The canvas draws an amber "behind the source" chip per locale per row.
- **C2 — dismissing the stale notice.** 23.10 §7 keeps the dismissal and makes it a separate fact
  beside the per-leaf verdicts. The canvas has no dismiss control at all.

### Constraints

- Payload admin component slots: a list column is a field (`type: "ui"` with `admin.components.Cell`) added to the collection — a schema-visible change to every enabled collection, and the plugin config builder has no slot for it yet.
- `/field` reads the **saved** source; the design's field control matches that (R17, R18).
- The runner's `stop` / `run` capabilities decide whether cancel / run routes exist; every new action must respect them.
- Translator UI deps (Radix, React Query, zod) are deliberate; the design note recommends Payload's Pill and Tooltip — a choice, not a given (Q6).
- `apps/dev` runs against the built plugin: rebuild before checking in the sandbox.

## Non-functional scan

- Performance — relevant: R10 must be one request per page; the field tree and per-leaf verdicts on a large document must not walk the document per leaf.
- Security / access — relevant: every new endpoint goes through the existing access guard; R14's list-query enqueue must not reach documents the user cannot read.
- Accessibility — relevant: R19 (shape + colour, focusable tooltips, real buttons/checkboxes).
- i18n — relevant: locale names shown in their own language ("Deutsch", "Español"); plugin strings today are English only — no change asked.
- Observability — N/A: no new logging asked; unanswered leaves are already logged.

## Open questions

1. **Branch** *[resolved]* — the request says "this branch", but `feat/translator-the-engine-stands-alone` carries the uncommitted traversal-engine move. Answer: a new branch from `major/translator`.
2. **Size / order** *[resolved]* — the design spans three surfaces. Answer: five slices, see Size check.
3. **Features the design drops** *[resolved]* — publish-after-translation, dismiss staleness, Queued + Run now, abandoned, `targetSelection`, cancel-all for a collection. Answer: decided one by one in design (slice 5); C2 is one of them.
4. **List column and list-query enqueue in this major?** *[resolved]* — Answer: required for the major.
5. **"Translate all" semantics** *[resolved — see Decisions]* — every locale in its own way (behind → only behind, empty → whole, written by hand → overwrite?) or whole document everywhere? Matters because: overwriting hand-written locales silently contradicts R7.
6. **Payload Pill/Tooltip vs the plugin's Radix primitives** *[resolved — see Decisions]* — the design note leans on Payload's; the plugin deliberately owns its primitives. Matters because: mixing both gives two tooltip behaviours.
7. **How the panel opens** *[resolved — see Decisions]* — no board shows the trigger. Keep today's icon + aggregate dot, now opening a drawer?
8. **Progress unit** *[resolved — dropped, see Decisions]* — leaves done / total, or chunks? Not covered by 23.10. Matters because: a run with one huge rich text sits at 0% then jumps.
9. **"Written by hand" detection cost** *[resolved]* — 23.10 §2: free on the document (the read with `fallbackLocale: false` already happens); the list column does not need it under 23.10 §5.
10. **Required fields** *[resolved]* — 23.10 §3: `mustInclude` = required and empty in the target, a permanent lock separate from the first-run lock.
11. **Field control inside localized blocks/arrays** *[resolved — see Decisions]* — `/field` refuses those today; the design does not draw that state.
15. **Partial run inside a block list localized as a whole** *[confirmed — non-blocking for the UI, blocking for shipping the field tree]* — checked on 2026-11-13 with a throwaway `translateContent` probe (removed after the run). Setup: a localized `blocks` list with leaves marked `localized: true`, source block `a1` (heading, body), target block `x7` with a hand-written German body, selection = the heading only. Result: the written block holds the translated heading **and the English body**, and has no id. The target's hand-written body is replaced by source text: the target block is not matched (ids differ per locale), so the reconciler fills every unselected leaf from the source. With a shared (non-localized) list the same run keeps the German body and the block id. A whole-document run is unaffected because every leaf is translated; it rebuilds the list from the source, as documented in `2026-06-12-cross-locale-block-identity.md`. Matters because: the field tree and "Update" (stale only) make partial runs routine. Before the tree ships, a partial run must either treat a localized block list as all-or-nothing or refuse it. Not checked: the full plugin path end to end.

12. **Failure / empty / loading states** *[non-blocking]* — no board shows the panel loading, a status request failing, or a document with no target locales configured.
13. **Selection-bar button** *[non-blocking]* — Payload 3.90.1 has no slot in the selection bar; the fallback is the counted button above the table, as today.
14. **Drift in the list column (C1)** *[resolved]* — the canvas shows "behind the source" per locale per row; 23.10 §5 keeps drift out of the list because it costs a read and a hash of every document on the page. The owner wants this checked, not taken as given, because provenance should make drift knowable precisely. Checked:
    - Today drift is read-time only. `DocumentStaleness.getStaleness` (`server/modules/provenance/DocumentStaleness.service.ts`) reads the source document and hashes it on every request. The receipt stores only the source **as translated** (`sourceFingerprint`, `translatedAt` in `Provenance.collection.ts:30-31`), never the source **as it is now**.
    - The current source is already hashed at save time. The auto-translate hook calls `hasSourceContentChanged` (`core/domain/auto-translate/hasSourceContentChanged.ts:24-25`) with the same `fingerprintOf` on every source-locale save that passes its gates (`server/modules/auto-translate/AutoTranslateEnqueue.hook.ts:65-70`).
    - So there is a precise option: store the source's current per-leaf fingerprint when the source is saved, next to the receipts. Drift then becomes a comparison of two stored values by the same `driftedAddresses` rule, and the list reads the sidecar collection only, with no document read. Costs to weigh in design:
      - a third write path into provenance;
      - writes that bypass hooks (bulk edit with hooks off, migrations) leave the snapshot behind;
      - a change to which fields are translatable changes the ruler without any save.

    One more finding: the rows of one list page can be read in a single query, so computing on the fly may be cheap enough. This has to be measured before anything is stored.

    Deferred by the owner to the end of the major (R21). Slice 1 builds no drift below the document's locale.

Restate check:
- "Behind" = the receipt says the leaf's source hash moved, **or** no run covered it, **or** the run left it empty — the design counts all three in "N fields behind" and separates only the last by "!". Confirmed by the DocumentTree board (Meta description: "no run has covered this field" carries the amber dot).
- "Not translated" vs "written by hand" = both lack a receipt; they differ only by whether the target locale has content. Not computable today.
- "Up to date" without provenance does not exist — R8 says "Translated" instead.

## Risks & constraints

- The list column touches every enabled collection's config (a UI field); it shows in generated types and the admin's column picker.
- Three new reads (full status, field tree, bulk preview) on top of the existing ones — design them as one or two endpoints, not five.
- Container mode for rich text changes what a "leaf" is; tree counts must use the same ruler as the stale check (cf. `2026-11-12-one-ruler-for-translatable-content.task.md`).

## Decisions by the owner

- 2026-11-13 — a block list localized as a whole is still replaced as a whole in the target on every translation. The target's order follows the source, and hand edits inside its blocks are lost; both are accepted. Blocks that exist only in the target are lost too. Keeping them would make every run add duplicates, because the plugin cannot tell its own earlier copies from blocks a person added: each copy gets a new id. The replacement is stated openly: a line in the docs (proposed to the owner, not edited in), and a hint in the UI where such a translation is started, like the "written by hand" warning. Keeping hand-added blocks needs the source-to-target block link and goes with the per-field translation of such blocks, after the major.

- 2026-11-13 — inside a block list localized as a whole, the field control is shown disabled with a hint to translate the whole document. The reason is that each locale's copy of such a list has its own block ids, so the source block cannot be found (`2026-06-12-cross-locale-block-identity.md`). How per-field translation could work there is a separate question to research. It is not part of this redesign.
- 2026-11-13 — nothing more is built for block lists localized as a whole in this major. What ships: the disabled field control with its hint, and a line in the plugin's docs recommending a shared block list with localized fields inside for anyone who needs per-field translation inside blocks. The docs line goes to the owner as proposed text and is not edited in. A possible later fix is to record, at translation time, which target block was made from which source block; it would cover only blocks the plugin created.

- 2026-11-13 — the never-attempted ("abandoned") locale gets its own state in the UI (R25): the server already stores it, so the UI should not hide it.

- 2026-11-13 — Cancel takes a run off the queue; it does not stop a translation in progress. Cancel and Retry exist only for a queue-based runner, and the server's abilities decide whether they are rendered. Correction to an earlier claim in this research: Retry already works on a failed job (`PayloadJobsTaskRunner.run` clears `hasError` and runs it again); only a succeeded job answers 404.
- 2026-11-13 — no progress bar in this version: measuring progress needs too much inside the run for what it shows (R24).
- 2026-11-13 — refreshing the panels after a translation or a save is functional work, not design, and it is in scope (R23).
- 2026-11-13 — loading, failure and no-locales states are added (R22).

- 2026-11-13 — the panel opens from today's trigger (icon + aggregate dot) and is a side drawer, not a popover.
- 2026-11-13 — "Translate all" translates every target locale by the condition set on screen and nothing else; a locale written by hand is overwritten. The plugin does not decide implicitly what to skip, because that is the guessing the plugin is moving away from.
- 2026-11-13 — components look like Payload's. A Payload component is reused only where it is reusable without workarounds; otherwise the plugin builds its own, by hand or on third-party primitives.
- 2026-11-13 — dismissing the stale notice stays; it already exists and the canvas omitting it is not a decision to drop it.
- 2026-11-13 — the queued state with "Run now" stays, gated on the runner's ability.
- 2026-11-13 — a translation started by hand always writes a draft; the "publish after translation" checkbox leaves the UI. Auto-translate keeps publishing the translation when the source is published, as it has since it was introduced, because nobody is watching an automatic run. The difference is stated in the UI by a hint, for example on the panel's auto-translate line and next to the manual actions; where exactly is a design decision.
- 2026-11-13 — the `targetSelection` setting is removed: the document panel acts per locale, the collection panel always offers locales as checkboxes (one or several). Listed in the major's migration notes.
- 2026-11-13 — cancelling every queued run of a collection at once stays, in the collection panel, gated on the runner's ability; without it a bulk run can only be stopped document by document.
- 2026-11-13 — the field tree ships in this major, not later. The per-leaf drift marks inside it stay deferred (R21).

- 2026-11-13 — drift is shown per document locale only ("N fields behind"); everything finer or wider — the list column's drift chip, per-field marks in the tree and the field control, the Behind / All switch, the bulk behind-field count — is deferred to the end of the major and decided then (R21). Whether drift for many documents is computed on the fly (one batched read per list page) or from a stored source fingerprint (a field on a plugin collection, cheapest to add together with the major's `translator-runs` migration) is part of that later decision. Q14 is closed by this deferral.

- 2026-11-13 — the UI is built on a new branch from `major/translator`, after the traversal-engine move lands, so neither diff hides the other.
- 2026-11-13 — the work is split into the five slices under Size check, in that order.
- 2026-11-13 — each current feature the canvas does not show is kept, moved or dropped by its own decision, taken in design.
- 2026-11-13 — the list column (R10) and translating the current list view (R14) ship with the major.
